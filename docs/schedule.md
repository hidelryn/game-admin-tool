# 스케줄(라이브 운영 일정) 설계

> 상태: **완료** (2026-11-15) — 화면 미리보기는 피드백으로 제외

## 1. 목표

운영자가 게임의 기간 일정(랭킹 시즌, 게임 이벤트)을 한 곳에서 관리하고,
일정마다 게임 안에서 **팝업·배너로 노출할지**를 정한다. 게임 서버는 "지금 보여줄 것"을 API 로 받아 간다.

결정 사항 (2026-11-15 사용자 선택)

| 항목 | 결정 |
|---|---|
| 랭킹 시즌 | 스케줄에서 생성·관리. 시작·종료 시각에 자동 전환, 종료 시 점수 기록 차단 + 최종 스냅샷 자동 생성 |
| 이미지 | 백오피스에서 업로드 (로컬 저장 → 배포 시 S3, 저장소 분리) |
| 일정 종류 | 랭킹 시즌 · 게임 이벤트 (공지·점검은 별도 기능으로 분리 — 2026-11-15 변경) |
| 확인 방법 | 게임 서버용 API(시뮬레이터가 호출해 로그로 확인). 백오피스 화면 미리보기는 만들었다가 피드백으로 제외 |

## 2. 일정 종류

| kind | 예 | 특이사항 |
|---|---|---|
| `RANKING_SEASON` | 아레나 시즌 2, 월드아레나 시즌 1 | 랭킹 시즌 1:1 연결, **랭킹 종류(보드) 필수**, 종료 시각 필수, **같은 보드 안에서만** 기간 겹침 금지 |
| `EVENT` | 경험치 2배, 한정 상점 | 설명 텍스트 (보상 배율 같은 실제 효과는 게임 쪽 범위 — 이번엔 표시만) |

## 3. 데이터

```
schedules
  id, kind, title(≤50), description(≤1000)
  starts_at, ends_at(필수)
  ranking_season_id (kind=RANKING_SEASON 일 때 1:1)
  -- 노출
  popup_enabled, popup_frequency(ONCE|DAILY|EVERY_LOGIN)
  banner_enabled, priority(정렬, 높을수록 앞)
  image_asset_id, link(게임 내 이동: game://… 또는 https://…)
  canceled_at, created_by, updated_by, created_at, updated_at
  version  -- 낙관적 잠금 (두 운영자가 동시에 고치면 뒤 사람은 409)

assets  (업로드 이미지)
  id, storage_key(UUID 파일명), mime, size, width, height, sha256,
  original_name, created_by, created_at

ranking_seasons
  status: SCHEDULED | ACTIVE | ENDED   ← SCHEDULED 추가
ranking_snapshots.kind: RESET | BACKUP | FINAL   ← FINAL(시즌 종료) 추가
```

- 상태(예정·진행·종료·취소)는 저장하지 않고 **시각으로 계산** → 워커가 늦어도 화면·게임 API 는 정확
- 시즌의 `ranking_seasons.status` 만은 점수 기록 판단에 쓰이므로 워커가 전환 (아래 4장)

## 4. 랭킹 시즌 수명 주기

```
[예정 SCHEDULED] --starts_at--> [진행 ACTIVE] --ends_at--> [종료 ENDED + FINAL 스냅샷]
```

- 워커 `season-lifecycle` (1분마다): 조건부 UPDATE(`WHERE status='SCHEDULED' AND starts_at<=NOW()`)로 전환 → 여러 워커가 돌아도 한 번만
- 종료 시: 같은 트랜잭션에서 상태 ENDED + FINAL 스냅샷 생성(시즌당 1개, 중복 방지 키). 점수는 지우지 않음(초기화와 다름) → 종료 시즌 순위는 계속 조회 가능
- **점수 기록 검사 추가**: 진행 중 시즌이 아니거나 기간 밖이면 거부 (`SEASON_NOT_ACTIVE`). 지금은 종료된 시즌에도 기록되는 구멍이 있음
- FINAL 스냅샷에서 바로 "순위 보상 우편"(기존 기능, L3) 진행 가능 → 시즌 종료 → 보상까지 한 흐름
- 시즌 기간은 서로 겹칠 수 없음 (같은 아레나 모드 1개 기준)

## 5. 위험도와 규칙

| 작업 | 위험도 | 규칙 |
|---|---|---|
| 일정 생성, 시작 전 일정 수정·취소 | L1 | 사유 + 운영 로그 |
| **진행 중 일정 수정** (기간 변경 등) | **L2** | 영향 미리보기 확인 후 실행. 시즌 종료 시각 변경은 "보상 대상이 바뀔 수 있음" 경고 |
| **진행 중 시즌 조기 종료** | **L2** | 종료 시각을 지금으로 → 다음 워커 주기에 종료 처리 |
| 진행 중 이벤트 내리기 | L2 | 취소(canceled_at) — 게임 노출 즉시 중단 |
| 종료된 일정 | 수정 불가 | 기록 보존 |
| 진행 중·종료 시즌 삭제 | 불가 | 점수·보상 이력 보존 |

- 권한 신설: `schedule:read`(전 역할), `schedule:manage`(최고 관리자·운영자)
- 시각 입력은 KST, 저장은 UTC

## 6. 이미지 업로드 (보안 주의 ⚠️)

- `POST /assets` — 본문에 이미지 바이트 그대로(멀티파트 라이브러리 불필요), 최대 **2MB**, `schedule:manage`
- **확장자·Content-Type 을 믿지 않고 파일 앞부분(매직 바이트)으로 판별**: PNG·JPEG·WebP 만 허용, **SVG 금지**(스크립트를 품을 수 있음)
- 가로·세로 최대 2048px, 저장 파일명은 UUID(원래 이름은 표시용으로만)
- 제공 `GET /assets/:key` — 게임에서도 보이므로 공개, 대신 키는 추측 불가 UUID. 응답에 `X-Content-Type-Options: nosniff`, 판별된 형식의 Content-Type, 오래 캐시
- 저장소는 인터페이스로 분리: 로컬(`storage/uploads`, `.gitignore`) → Phase 7 에서 S3
- 링크는 `game://` 또는 `https://` 만 허용 (`javascript:` 등 차단)

## 7. 게임 서버용 API

`GET /internal/game/live-ops` (기존 내부 키 인증, 운영 환경 비활성 규칙 동일)

```json
{
  "now": "...",
  "popups":  [{ "id": 12, "title": "...", "imageUrl": "...", "link": "game://shop", "frequency": "DAILY", "priority": 10 }],
  "banners": [{ "id": 15, "title": "...", "imageUrl": "...", "link": "...", "priority": 20, "endsAt": "..." }],
  "season":  { "id": 2, "name": "아레나 시즌 2", "endsAt": "..." }
}
```

- 지금 진행 중이고 취소되지 않은 일정만, priority 높은 순
- 시뮬레이터가 매 틱 호출해 "진행 중 시즌이 없으면 점수 기록 안 함"을 따르고 로그로 노출 목록 출력

## 8. 화면 `/schedules`

- **타임라인(월간 간트)**: 종류별 색, 오늘 선, 막대 클릭 → 편집. 아래에 목록(필터: 종류·상태)
- **편집 서랍**: 종류별 입력(시즌은 종료 필수·겹침 검사), 노출 설정(팝업 빈도, 배너 우선순위), 이미지 업로드·미리보기, 링크
- 랭킹 화면: 시즌 선택에 "예정" 시즌 표시, 시즌 생성은 스케줄로 이동, 시즌 종료 시 FINAL 스냅샷에서 보상 지급 버튼

## 9. 범위 밖 (이번엔 안 함)

- **공지·점검** — 별도 기능으로 따로 설계 (점검 중 게임 API 차단 포함)
- 이벤트의 실제 게임 효과(경험치 배율 등) — 게임 로직 영역
- 반복 일정(매주 반복), 회원 대상 조건(신규 유저만 등)
- 팝업 노출 횟수 집계 (게임 클라이언트가 보고해야 함)

## 10. 작업 순서와 테스트

1. DB·공유 스키마·권한 시드 → 2. 이미지 저장소·업로드 → 3. 일정 API(L1/L2) → 4. 시즌 수명 주기 워커 + 점수 기록 검사
→ 5. 게임 API·시뮬레이터 → 6. 화면(타임라인·편집) → 7. 문서

테스트(통합): 시즌 자동 시작·종료·FINAL 스냅샷 1회(워커 동시 실행), 종료 시즌 점수 거부, 시즌 기간 겹침 거부, 진행 중 수정 L2,
동시 수정 409(version), 업로드 매직 바이트·SVG·크기 거부, 링크 스킴 거부, 게임 API 노출 규칙(기간·취소·우선순위)


## 11. 랭킹 보드 (2026-11-15 추가)

아레나·월드아레나처럼 **랭킹 종류가 여럿**이고 동시에 진행될 수 있어 보드 개념을 추가.

- `ranking_boards(id, code, name, sort_order)` — 시드로 고정: 1 `ARENA` 아레나(보드 도입 전 시즌 전부), 2 `WORLD_ARENA` 월드아레나. 화면에서 추가하는 기능은 필요할 때
- 시즌은 `board_id` 를 가진다. 겹침 검사·이름 잠금은 **보드마다**
- 게임 점수 API: `seasonId` 또는 `boardCode`(그 보드의 진행 중 시즌). 둘 다 없으면 진행 중 시즌이 하나일 때만 허용, 여러 개면 422 로 보드 지정 요구
- live-ops: `season` → `seasons[]` (보드별 진행 중 시즌, 보드 순서)
- 화면: 시즌 만들 때 랭킹 종류 선택, 타임라인·목록에 `[월드아레나] 시즌 1` 형태, 랭킹 화면은 보드 → 시즌 순으로 선택
