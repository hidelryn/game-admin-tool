# 유저 분석 (이탈 구간 · 리텐션 · 과금 · 재화 소비처)

> 2026-11-18 추가. 메뉴 "유저 분석"(`/analytics`), 권한 `analytics:read`, MCP 조회 Tool 4개.
> **모든 데이터는 가상**이다 — 실제 게임 운영 데이터를 쓰지 않는다.

## 1. 결정 사항 (사용자 승인)

| 항목 | 결정 |
|---|---|
| 구간 기준 | **스테이지 진행도** 10 단위. "다음 도전 스테이지" 기준 (최고 클리어 19 → 11~20 구간) |
| 결제 데이터 | `products`·`purchases` 표 추가. 금액(원)·지급 젬·결제 당시 스테이지 기록 |
| 가상 데이터 | 시드·시뮬레이터·체험 활동을 **순서대로 진행 + 난이도 벽(20·45·80)** 모델로 변경 |

## 2. 화면 (탭 4개, 조회 전용)

| 탭 | 내용 |
|---|---|
| 이탈 구간 | 이탈 기준(3·7·14·30일 미접속) 선택 → 구간별 이탈률 막대 + 표(도달·멈춤·이탈·이탈률) |
| 리텐션 | 가입일 코호트 × D1·D3·D7·D14·D30 재접속률 표 (단일 색 명도), 가중 평균 행 |
| 과금 | 매출·결제자·결제율·ARPPU, 첫 결제 구간, 구간별 매출, 첫 결제까지 걸린 기간, 상품별 매출 |
| 재화 소비처 | 재화 선택 → 사유별 소비량·비중, 진행 구간별 소비 |

- 기간: 7·30·90일 (API 최대 90일, KST 날짜)
- "표로 보기" 스위치 — 모든 차트를 표로 (색만으로 읽지 않게)
- 차트는 한 축만 (이중 축 금지), 상위 3개 막대에만 값 라벨

## 3. 정의

| 지표 | 정의 |
|---|---|
| 이탈 | 탈퇴 제외, **가입 후 N일 이상 지난 회원** 중 마지막 접속(없으면 가입 시각)이 N일 이상 지난 회원 |
| 도달(reached) | 그 구간 이상까지 온 판정 대상 회원 |
| 이탈률 | 그 구간에서 멈춘 채 이탈한 회원 ÷ 도달 |
| 리텐션 D-n | 가입일(KST)로부터 정확히 n일째(KST 날짜)에 LOGIN 이 있는 회원 비율. 아직 그날이 안 왔으면 null |
| 결제율 | 기간 결제자 ÷ 기간 접속자 |
| ARPPU | 기간 매출 ÷ 기간 결제자 |
| 첫 결제 | 회원의 첫 결제(전체 기간 기준)가 조회 기간 안인 경우만 |
| 소비처 | 원장 `source=GAME` 의 음수만 (운영자 회수·우편 제외). 구간별 소비는 회원의 **현재** 구간 기준 (원장에 당시 구간이 없음) |

## 4. 가상 플레이 모델 (`apps/api/src/modules/analytics/game-model.ts`)

시드·시뮬레이터·체험 모드 가상 활동이 **같은 함수**(`planSession`)를 쓴다. 난수 함수를 받으므로 시드는 결정적.

- 접속 1회 = 1~4번 도전. 다음 스테이지만 도전(순서대로). 일반 스테이지 클리어 확률 0.96 → 점점 낮아짐(최저 0.6)
- **벽**: 20(0.16) · 45(0.11) · 80(0.07). 막히면 결제(첫 결제 3%, 재결제 15%) 후 유료 젬 부활(성공률 +0.5), 또는 무료 젬 부활
- 재화: 클리어 보상 골드 / 장비·스킬 강화 골드 소비 / 부활·뽑기 젬 소비 / 일일 미션 무료 젬 / (실시간만) 행동력 회복·입장
- 이탈: 벽에 막힌 채 끝나면 11%, 1~5 스테이지 7%, 그 외 1.2% (결제자는 40% 수준)
- 시드: 가입일부터 하루씩 시뮬레이션. 기간(30·60일) 이전은 상태만 계산하고 잔액을 "이전 기록 이월" 1건으로 → 원장 합계 = 잔액 유지
- 실시간(시뮬레이터·체험): **최근 3일 안에 접속(또는 가입)한 회원만** 샘플 → 이미 떠난 회원이 되살아나 이탈 분석이 흐려지지 않게

5,000명 × 45일 모의 실행 결과(참고): 11~20·41~50 구간에서 이탈·첫 결제가 몰리고, 결제자 약 8%.

## 5. 데이터

| 표 | 내용 |
|---|---|
| `users.max_stage` | 최고 클리어 스테이지. STAGE_CLEAR 이벤트로 `greatest()` 갱신 (줄지 않음) |
| `products` | 가상 상품 6종 (스타터 패키지·젬 60/330/700/2,400·월정액), id 고정, 시드 |
| `purchases` | 결제 기록 (append only, FK 없음): 상품·가격·젬·결제 당시 스테이지·시각. 인덱스 `(purchased_at)`, `(user_id, purchased_at)` |
| 원장 `source=PURCHASE` | 결제로 받은 유료 젬 — 결제 기록과 같은 트랜잭션 |

결제 경로: 내부 게임 API `POST /internal/game/purchases` (시뮬레이터, 운영 환경 비활성) · 체험 모드 worker 가 서비스 직접 호출. **운영자가 결제를 만드는 화면·API 는 없다.**

## 6. API · MCP

| Method | Path | 설명 |
|---|---|---|
| GET | `/analytics/churn?inactiveDays=7` | 이탈 구간 |
| GET | `/analytics/retention?from&to` | 코호트 리텐션 |
| GET | `/analytics/purchases?from&to` | 과금 |
| GET | `/analytics/spending?from&to&currencyCode=GOLD` | 재화 소비처 |

- 권한 `analytics:read` — 최고 관리자·운영자·조회 전용 (고객지원 제외). 체험 계정 토큰에도 허용 (조회)
- 실시간 집계 + Redis 10분 캐시 (`analytics:*`)
- MCP: `analyze_churn` · `analyze_retention` · `analyze_purchases` · `analyze_spending` (읽기 전용)
