# 체험 모드 · 안내 캐릭터

> 상태: **구현 완료, 확인 대기** (2026-11-17). Live2D 모델은 파일을 받으면 교체 예정

포트폴리오 방문자가 로그인 화면에서 바로 체험 계정으로 들어와, 안내 캐릭터 "하루"(Live2D)의 메뉴 투어를 따라 둘러볼 수 있게 한다.

## 1. 결정 (2026-11-17 사용자 선택)

| 항목 | 결정 |
|---|---|
| 체험 계정 | **운영자 권한** + **매일 04:00(KST) 초기화** |
| 안내 범위 | 로그인 화면 소개 + 로그인 후 **메뉴 투어** (언제든 "둘러보기") |
| 캐릭터 | 밝은 애니풍 여캐, **Live2D** 로 쓰고 싶음 → 모델은 공식 무료 샘플(추천: 하루 접수원 버전)·구매·의뢰 중 사용자가 준비. → **공식 샘플 하루(접수원 버전) 적용** ([live2d.md](live2d.md)) |

## 2. 설정 (`.env`)

| 변수 | 기본 | 설명 |
|---|---|---|
| `DEMO_MODE` | `false` | 로그인 화면에 체험 계정 표시 + 체험 계정 생성·제한 |
| `DEMO_ACCOUNT_EMAIL` | `demo@example.com` | 체험 계정 이메일 |
| `DEMO_ACCOUNT_PASSWORD` | — | `DEMO_MODE=true` 면 필수 (10자 이상, 영문·숫자). **코드에 두지 않는다** |
| `DEMO_DAILY_RESET` | `false` | ⚠️ 매일 04:00 KST 데이터 전체 초기화. `DEMO_MODE` 없이 켜면 **기동 실패** (실수로 운영 데이터를 지우지 않게) |

- 체험 계정은 `npm run db:seed` 와 worker 기동 때 env 값에 맞춰 만들어지거나 갱신된다 (비밀번호를 바꾸면 worker 재시작).

## 3. 체험 계정 제한

| 항목 | 처리 | 이유 |
|---|---|---|
| 권한 | 운영자(OPERATOR) — 지급·회수·우편·공지·스케줄·점검 가능, 전체 우편·랭킹 초기화 등 최고 관리자 작업은 불가 | 직접 해 보는 체험 |
| 비밀번호 변경 | 403 `DEMO_RESTRICTED` (메뉴도 비활성) | 한 사람이 바꾸면 다른 방문자가 못 들어옴 |
| API 토큰 발급 (MCP 체험) | 허용하되 **조회 권한만**(`DEMO_TOKEN_PERMISSIONS`), 만료는 **다음 초기화까지**, 체험 계정 전체 **동시 20개**, 발급은 **IP 당 시간당 3회**(429), 초기화 때 전부 삭제 | 방문자가 MCP 연결까지 체험하되, 공개 토큰으로 데이터를 바꾸거나 오래 쓰는 것 방지 |
| 로그인 실패 잠금 | 적용 안 함 (IP 당 분당 시도 제한은 유지) | 일부러 틀려서 계정을 잠그는 장난 방지 |
| 표시 | `/auth/me` 의 `isDemo`, 상단 "체험 계정 · 매일 04:00 초기화" | |

## 4. 매일 초기화 (worker `demo-reset`, 04:00 KST)

1. 표 비우기 — **남기는 표**: 운영자·역할·권한·개별 권한, API 토큰(체험 계정 토큰은 따로 삭제), 로그인 세션, 마이그레이션 기록
2. Redis — 이 환경 접두어의 키 중 작업 큐(`bull*`)만 남기고 삭제
3. 업로드 이미지 파일 삭제
4. 기준 데이터(재화·랭킹 보드·시즌 등) → 가상 회원·활동(small, 1천 명) → 체험 계정 → KPI 다시 집계
5. 운영 로그에 `DEMO_RESET`(SYSTEM) 1건

운영 서버(Compose)에서는 worker 에도 업로드 볼륨을 붙여 3번이 동작한다.

## 5. 화면

- **로그인**: 왼쪽에 하루 + 말풍선 + 프로젝트 소개·기술 스택, 오른쪽에 로그인 폼 + 체험 계정 카드(복사, "체험 계정으로 로그인", 다음 초기화 시각). 정보는 `GET /api/v1/public/demo` (인증 없음, 체험 모드가 꺼져 있으면 `enabled:false` 만)
- **메뉴 투어**: antd Tour. 권한 있는 메뉴만 순서대로, 단계마다 하루 상반신 + 분위기(기본·기쁨·윙크·주의 → 몸짓 모션). 체험 계정은 첫 로그인에 자동 시작(브라우저에 본 기록 저장), 누구나 상단 "둘러보기"로 다시
- **캐릭터 교체 지점**: `apps/web/src/shared/guide/GuideCharacter.tsx` 하나 — Live2D 모델을 받으면 이 안에서만 바꾼다

## 6. Live2D 로 바꿀 때 필요한 것

- 모델 `runtime` 폴더(`.model3.json`·`.moc3`·텍스처·모션), Cubism SDK for Web 의 `live2dcubismcore.min.js` — 둘 다 사용자가 라이선스에 동의하고 직접 받는다
- 공식 샘플을 쓰면 해당 캐릭터의 저작권 표기를 로그인 화면에 넣는다
- 로그인 화면·투어에서만 불러오고, 실패하거나 '동작 줄이기' 설정이면 정지 그림으로

## MCP 체험 시 주의 (보안)

- 공개 계정이라 **누구나 서버 API 에 접근하는 토큰을 받을 수 있다.** 조회 권한만이라 데이터를 바꿀 수는 없지만, 조회 API 를 반복 호출하는 부하는 막지 못한다 → 운영 서버에 일반 API Rate Limit 을 두는 것을 권장
- 같은 계정을 쓰므로 토큰 목록에 다른 방문자의 토큰(이름·앞부분)이 보이고 **폐기도 할 수 있다** — 원문은 발급자에게 한 번만 보이므로 유출은 아님. 초기화로 정리됨
- 체험 계정 토큰에 쓰기 권한(지급·우편 등)을 주려면 `packages/shared/src/schemas/api-tokens.ts` 의 `DEMO_TOKEN_PERMISSIONS` 를 고친다 (확인 토큰 절차는 그대로 적용됨)
