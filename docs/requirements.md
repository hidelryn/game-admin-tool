# 요구사항 정의서

> 상태: **Phase 1 초안 — 검토/승인 대기**
> 표기: `[가정]` = 승인 전 임시 가정, `[결정 필요]` = development-log.md의 결정 필요 사항과 연결

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 게임 운영자가 웹 백오피스 또는 AI 클라이언트(MCP)로 동일한 운영 기능을 안전하게 수행 |
| 사용자 | 게임 운영자(내부 직원). 게임 플레이어는 이 시스템의 사용자가 아님 |
| 데이터 | 실제 게임이 없으므로 **가상 게임 "Project Arena"(가칭)** 의 시드/시뮬레이션 데이터 사용 `[가정]` |
| 성격 | 포트폴리오 — 실제 운영 수준의 구조·안정성·보안을 보여주는 것이 핵심 |

### 1.1 가상 게임 도메인 `[가정]`

실제 게임 서버가 없으므로 백오피스가 관리할 "게임 데이터"를 최소 범위로 정의한다.

| 도메인 | 정의 |
|---|---|
| 회원(플레이어) | 계정 ID, 닉네임, 레벨, 가입일, 최근 접속일, 상태(정상/정지/탈퇴) |
| 재화 | `GOLD`(골드, 무료), `GEM`(유료 젬), `FREE_GEM`(무료 젬), `STAMINA`(행동력) 4종 — 유료/무료 젬은 잔액을 분리해 환불·매출 집계와 MCP 확인 대상을 구분 |
| 아이템 | 우편 보상용 마스터 데이터(예: 강화석, 경험치 물약, 스킨 상자) |
| 활동 이력 | 로그인/로그아웃, 스테이지 클리어, 아이템 사용, 재화 획득·소모, 우편 수령 |
| 랭킹 | 시즌제 점수 랭킹(예: 아레나 시즌 점수) |

시드 스크립트와 **활동 시뮬레이터**(가짜 플레이 이벤트 생성)를 제공해 대시보드·이력 화면에 의미 있는 데이터가 보이도록 한다.

## 2. 기능 요구사항

우선순위: **M**(필수) / **S**(권장) / **C**(확장 고려, 이번 범위 아님)

### 2.1 운영자 관리 (FR-ADM)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-ADM-01 | 이메일 + 비밀번호 로그인, 로그아웃 | M |
| FR-ADM-02 | JWT Access Token(단기) + Refresh Token(장기, 회전) 인증 | M |
| FR-ADM-03 | 로그인 5회 연속 실패 시 15분 잠금 | M |
| FR-ADM-04 | 운영자 계정 생성/조회/수정/비활성화 (삭제 대신 비활성화) | M |
| FR-ADM-05 | 역할(Role) 기반 접근 제어 — 운영자당 1개 역할 | M |
| FR-ADM-06 | 운영자별 권한 개별 추가/제외(Override) | M |
| FR-ADM-07 | 최초 로그인 / 관리자 초기화 시 비밀번호 변경 강제 | S |
| FR-ADM-08 | MCP용 API 토큰 발급/폐기 (권한 범위·만료일 지정) | M |
| FR-ADM-09 | 2단계 인증(TOTP) | C |

| ID | 요구사항 | 우선순위 |
|---|---|---|

| FR-USR-03 | 회원 상세 — 기본 정보, 재화 요약, 정지 이력, 최근 활동 | M |
| FR-USR-04 | 회원 정지 — 사유 필수, 기간(일 단위 또는 영구) | M |

### 2.3 재화 관리 (FR-CUR)

|---|---|---|
| FR-CUR-01 | 회원별 재화 잔액 조회 | M |

## 4. 비기능 요구사항 (NFR)

| 분류 | 요구사항 |
|---|---|
| 성능 | 목록/상세 API p95 < 300ms (회원 10만 명, 활동 이력 500만 건 기준 시드), 랭킹 조회 p95 < 50ms |
| 정합성 | 재화 변경은 DB 트랜잭션 + 행 잠금. 잔액과 원장 합계 불일치 0건 |
| 가용성 | Redis 장애 시 랭킹 외 기능은 정상 동작 (중복 방지는 DB 유니크 제약으로 최종 보장) |
| 보안 | OWASP Top 10 대응, 비밀값 하드코딩 금지, 최소 권한 원칙 |
| 감사성 | 누가·언제·무엇을·왜·어떤 채널로 했는지 100% 추적 |
| 유지보수성 | 계층 분리(Route → Controller → Service → Repository), 공용 타입/스키마 공유 |
| 테스트 | 서비스 계층 단위 테스트 커버리지 80% 이상 목표, 핵심 시나리오 통합 테스트 |
| 관측성 | 구조화 로그(JSON), 요청 ID 전파, 헬스 체크 엔드포인트 |
| 이식성 | `docker compose up` 한 번으로 전체 로컬 환경 실행 |

## 5. 범위 밖 (Out of Scope)

- 실제 게임 클라이언트/게임 서버 구현 (시뮬레이터로 대체)
- 결제/환불 연동, 다국어(i18n), 다중 게임/다중 서버(월드) 지원
- 예약 발송 실행 기능, 2FA, SSO — 설계상 확장 지점만 남김
- 클라우드 **자동** 배포(CD 무중단) — 배포는 GitHub Actions에서 수동 승인 후 실행하는 방식까지
- 고가용성 구성(다중 인스턴스, 관리형 DB 이중화) — 단일 VM 기준

## 6. 용어

| 용어 | 정의 |
|---|---|
| 운영자(Admin) | 백오피스 사용자 |
| 회원(User/Player) | 게임 플레이어 |
| 채널(Channel) | 작업이 들어온 경로 — `WEB`, `MCP`, `SYSTEM`(배치) |
| 원장(Ledger) | 재화 변경 거래 기록 테이블 |
| Idempotency Key | 같은 요청의 중복 실행을 막기 위해 클라이언트가 보내는 고유 키 |
| 확인 토큰(Confirmation) | 위험 작업을 바로 실행하지 않고 미리보기를 본 뒤 같은 내용으로 다시 요청할 때 쓰는 1회용 토큰 (2026-11-16 승인 요청 레코드 방식에서 변경) |
